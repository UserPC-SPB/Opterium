# Witness Prover: machine-checkable proof certificates for Opterium

> **Epistemology, not just automation.** This folder implements the proof
> model that §2 of [Borisov_K_theory.md](../../Theory/ontology_of_number/Borisov_K_theory.md)
> describes: *"Proof is NOT deduction from axioms. Proof
> IS the closure of multiple independent routes on the same address, with
> zero residual tension, certified by an explicit verification procedure."*
> The program turns that definition into concrete, machine-readable,
> re-checkable certificate files.

## How it differs from Lean — and why it is stricter

**Lean** creates proofs as *terms inside a formal system with axioms*. A
Lean proof is trustworthy **only if every axiom is true**. Garbage axioms →
valid-looking but meaningless proofs (the formal system cannot detect that
the foundations are false).

**This prover** trusts no axioms — none exist here: Opterium forbids
introducing anything unjustified or merely postulated — and it does not even
trust the engine.
A claim is certified only when:

1. several **independent witness routes** (different computation paths to
   the same address) all close exactly — `tau = 0`; and
2. a **kernel routine re-derives the claim from first principles** using
   only exact standard-library arithmetic, never reading engine output.

So the certificate is a **reproducible computation record**, not a
chain of unexamined postulates (Opterium admits none at all). Any third party can re-run the kernels and get bit-identical
verdicts — including on a machine that has never seen the engine.

## Using the compiled cube_v5 engine

The prover decides every verdict by itself (`prover_kernel.py`); the engine is
**optional supporting evidence** — its live witness is attached to each
certificate for cross-reference only. The engine ships **compiled**: no
source, only a binary core (`core/cube_v5.pyd`, or bundled inside
`mcp_server.exe`) plus the data blob `cube_v5.bin` (272 MB; integrity via
`cube.sha256`).

### Distribution layout

The distribution (not committed in this tree — the 272 MB blob is too large
for plain git) contains:

```
cube_v5/
├── mcp_server.py        # MCP server: exact-math tools over stdio JSON-RPC
├── launch_mcp.py        # self-locating launcher (chdir to own dir, run server)
├── core/cube_v5.pyd     # compiled core — no source shipped
├── cube_v5.bin          # data blob (272 MB)
└── cube.sha256          # sha256 of cube_v5.bin
```

A standalone PyInstaller build (`mcp_server.exe` + runtime DLLs) is also
available and needs no Python at all.

### Starting the server

```bash
python launch_mcp.py        # package form (Python 3.11-3.13)
mcp_server.exe              # standalone bundle — no Python required
```

The server speaks **MCP over stdio (JSON-RPC)**: requests on stdin,
responses on stdout. Any MCP client can attach (e.g. the `toolfmt` gateway
runs it as an upstream: `python mcp_server.py`).

### Calling tools

After the MCP handshake use `tools/list` / `tools/call`. Values are passed as
strings and returned exactly — no floats, no rounding:

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"cubint_add","arguments":{"a":"7","b":"5"}}}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"cubint_pow","arguments":{"a":"3","b":"100"}}}
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"e8_get_root","arguments":{"idx":0}}}
```

Expected results: `12`,
`515377520732011331036461129765621272702107522001` (3^100, 48 digits), and the
root vector `[2, 2, 0, 0, 0, 0, 0, 0]` (norm squared 8).

## Usage

Run from the repository root:

```bash
python software/witness_prover/prover_top.py --list
python software/witness_prover/prover_top.py --cert T-e8-spectrum
python software/witness_prover/prover_top.py --run-all          # writes certificates/*.cert.json
python software/witness_prover/prover_top.py --run-all --no-engine
```

Optional: the program looks for the native engine
(`mcp_server.exe` in `D:\cube_v5_native\mcp_server\` or `$CUBE_V5_EXE`)
and, if present, attaches the engine's **live witness** to each certificate
as extra supporting material. The verdict is **never** decided by the
engine — only by the kernel.

## Certificate format (v1)

Each `certificates/*.cert.json` contains:

* `schema`, `certificate`, `statement`, `claims` — human/machine statement;
* `routes[]` — independent witness routes, each with `witness` (bool),
  `detail` (reproducible text), `route_hash` (SHA-256);
* `kernel_recompute` — first-principles recomputation verdict (the decisive
  piece);
* `closure` — `routes_total`, `routes_closed`, `kernel_ok`, `tau`, `verdict`;
* `engine_live_witness` — optional engine output for cross-reference only;
* `certificate_hash` — SHA-256 over statement+routes+kernel;
* `disclaimer` — Opterium is speculative geometry, not peer-reviewed.

Verdict is `CERTIFIED` iff `tau == 0` (all routes closed *and* kernel
recomputed the claim). Any deviation makes the certificate `UNRESOLVED` —
the harness refuses to certify what it cannot re-derive.

## Standards note

**No transcendental functions, no floats, no fitting.** Every kernel step
is exact integer or `Fraction` arithmetic. The certificates are therefore
deterministic, portable, and independently reproducible.

```bash
python software/witness_prover/prover_top.py --run-all --no-engine   # offline, reproducible
```

## For AI agents

- **Structure:** `prover_top.py` (CLI + certificate assembly) → `prover_kernel.py` (independent recomputation) → `certificates/*.cert.json` (generated; absent until `--run-all`).
- **Entry points:** `python software/witness_prover/prover_top.py --list`; `--cert <ID>`; `--run-all` (writes certificates). Run from the repository root.
- **Budget:** this README ~2 400 tokens; `prover_kernel.py` ~5 050; `prover_top.py` ~3 000.
- **Gotchas:** the native engine is optional and never decides the verdict; kernels use only exact integers and `Fraction`; `certificates/` is generated, not tracked; the theorem table above is the current certified set.
