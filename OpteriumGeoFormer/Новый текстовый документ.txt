## 0.1 AnchorFile как системный промпт
**Что:** Загрузить AnchorFile_SuperTable_v1.0 + lern1.txt как контекст в любую LLM.
**Зачем:** LLM начинает навигировать таблицу вместо вычислений.
**Как:** Системный промпт: "Используй таблицу для рассуждений. Не вычисляй — навигируй."
**Результат:** Opterium работает как грамматика рассуждений поверх существующей модели.

## 0.2 Debt System preprocessing
**Что:** Заменить float-арифметику в chain-of-thought на (mantissa, debt).
**Пример:**
```
LLM ошибается: 0.1 + 0.2 = 0.30000000000000004
Debt System:   (1,-1) + (2,-1) = (3,-1) = 0.3  (ΔT=0)
```
**Реализация:** Preprocessing слой перед LLM inference.

```

12 / 3 → найти пару с 3 → "3:4" → вернуть 4
```

## 3.1 Концепция
E8 roots генерируются из адреса `(x,y)` через gcd + seed mapping.
Проверка избыточна — выемка невозможна мимо.

```
g = gcd(x, y)

→ D8 root:    если seed ≤ 2 → (sx, sy, 0,0,0,0,0,0)
→ Spinor root: sign(sx)*1, sign(sy)*1, +1,+1,... + even parity
```

## МАТЕМАТИКА OPTERIUM (ФУНДАМЕНТ)

### Координаты S, D, P
Каждая ячейка (x, y) описывается тремя параметрами:
- **P (Product):** x * y
- **S (Sum):** x + y
- **D (Difference):** x - y

### Ключевое тождество
```
P = (S² - D²) / 4
```
Производство = интерференция между суммой и разницей.

Любые ДВЕ из (x, y, P, S, D) определяют ячейку:
```
(x,y) → P=xy, S=x+y, D=x−y
(S,D) → x=(S+D)/2, y=(S−D)/2, P=(S²−D²)/4
```

### Три кривые навигации
- **ГИПЕРБОЛА xy=P:** Все ячейки с одинаковым произведением. Делители P.
- **АНТИ-ДИАГОНАЛЬ x+y=S:** Прямая 45°. Продукты образуют параболу.
- **ДИАГОНАЛЬ x−y=D:** Знак D = результат сравнения a > b.

### Арифметика — это навигация
```
СЛОЖЕНИЕ:       Cell(a,b).S = a+b      O(1)
ВЫЧИТАНИЕ:      Cell(a,b).D = a−b      O(1) + знак = сравнение
УМНОЖЕНИЕ:      Cell(a,b).P = a×b      O(1)
ДЕЛЕНИЕ:        найти ячейку на xy=P   O(√P)
КВАДРАТНЫЙ КОРЕНЬ: гипербола пересекает диагональ  O(√P)
```

### Debt System (дробные числа)
```
0.23  = (23, −2)    meaning 23 × 10⁻²
2300  = (23, +2)    meaning 23 × 10²

Умножение: (m1,d1) × (m2,d2) → mantissa = m1×m2, debt = d1+d2
Сложение:  выровнять долги, сложить мантиссы
```
Ноль float ошибок. 0.1 + 0.2 = 0.3 ТОЧНО.

### Canon & Tag
```
canon(a,b) → (base_point, tag)
base_point = (min(|a|,|b|), max(|a|,|b|))  # всегда x ≤ y
tag = (sx, sy, swapped)
```

### prim поле (аналоговое рассуждение)
```
prim[2:6] = [1,3,2]   # seed=(1,3), scale=2
prim[3:9] = [1,3,3]   # seed=(1,3), scale=3
prim[4:12] = [1,3,4]  # seed=(1,3), scale=4
```
Все три — "одно и то же в разном масштабе". Аналогия через геометрию.

## СТРУКТУРА ТАБЛИЦ (PtTable)

```
_P[1025][1025]    # Таблица произведений: _P[x][y] = x*y
_S[1025][1025]    # Таблица сумм: _S[x][y] = x+y
_D[1025][1025]    # Таблица разниц: _D[x][y] = x-y

_SP[2049][2049]   # Таблица SD→P: _SP[S][D+offset] = P
                  # S = 0..2048, D = -1024..+1024 (offset=1024)

_prox[4097]       # Proximity веса: _prox[dist] = 10000 // (1 + dist)
                  # dist = |ΔS| + |ΔD|, max_dist = 4096

_isqrt[1025]      # Квадратные корни: _isqrt[n²] = n
_pow10[11]        # Степени 10: [1, 10, 100, ..., 10^10]
_abs[2049]        # Модули: _abs[v + offset] = |v|

by_P              # Индекс делителей: by_P[12] = [(1,12), (2,6), (3,4)]
```

**Размер:** ~28.1 МБ в бинарном формате `.ptbl`

### Бинарный формат .ptbl
```
Заголовок (256 байт):
  [0:4]   Magic: 'PTBL'
  [4:8]   Version: 1
  [8:12]  max_coord (uint32 LE)
  [12:16] offset (uint32 LE)
  [32:...] Offsets каждой таблицы (uint32 LE)

Данные:
  _P:    dim*dim * 4 байт (int32)
  _S:    dim*dim * 4 байт (int32)
  _D:    dim*dim * 4 байт (int32)
  _SP:   sp_dim*sp_dim * 4 байт (int32)
  _prox: prox_size * 4 байт (int32)
  _isqrt: isqrt_size * 4 байт (int32)
  _pow10: pow10_size * 8 байт (int64)
  _abs:  abs_size * 4 байт (int32)
```

## GCD-ДЕКОМПОЗИЦИЯ (числа > 1024)
```python
def _product_scaled(a, b):
    g = gcd(a, b)
    if g <= 1:
        return a * b  # fallback для взаимно простых
    seed = _product_scaled(a // g, b // g)
    return seed * g * g
```
Пример: 2048 * 2048 → gcd=2048 → seed=(1,1) → _P[1][1]=1 → result=1*2048²=4194304

## E8 ROOT LATTICE

### 240 корней
- **D8 roots (112):** два ±2, остальные 0. Все перестановки.
- **Spinor roots (128):** все ±1, чётное количество минусов.

### Генерация on-the-fly из адреса
```
g = gcd(x, y)
seed = (x/g, y/g)
→ D8 root:    если seed ≤ 2 → (sx, sy, 0,0,0,0,0,0)
→ Spinor root: sign(sx)*1, sign(sy)*1, +1,+1,... + even parity fix
```

### Dot product
```
dot(u, v) = Σ u[i] * v[i]  (8 lookup умножений + 7 сложений)
Результат ∈ {-8, -4, 0, +4, +8}
```

### Треугольники E8
2240 равносторонних треугольников. Все dot products = -4. Side² = 24.

## 3D СТРУКТУРА (Cube27, Addr3, Doctor)

### Addr3 — Ternary address stack
Каждый 3D адрес разворачивается в стек тритов (tx,ty,tz) ∈ {0,1,2}³.
```
Axis rule: все уровни (d,d,d) → x=y=z → D_body=0 → Doctor=zero tension
```

### Cube27 — Fractal 3×3×3 subdivision
```
27 subcubes, 3 on axis (0,0,0), (1,1,1), (2,2,2) — Doctor=CLOSED
24 off axis — Doctor reports tension
```

### Doctor Principle (6 каналов)
```
C1-C3: holographic (shadow closure)
C4: axis (ternary rule)
C5: phase roundtrip
C6: D_body agrees with axis
ΔT = count(failed channels)
```

### CubeCell
Полная 3D ячейка: V, S, C, D_body, phase, stack, perturbations, witnesses, vieta_check.
